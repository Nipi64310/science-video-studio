# 从主题到成片

1. **确认观众看完能带走的一句话。** 把题目收敛成一个具体问题。先查一手资料并写成可直接使用的事实摘要，区分官方说法、自己的推论和实测。
2. **先写可听的口播。** 用自然中文讲清因果；读起来像同事解释，不像博客或翻译稿。时长先估计，最终以配音为准。删内容优先于强行加速。
3. **逐镜设计动作。** 每镜写目标、口播、画面如何变化、声音和语义锚点。动画要补充解释，不只重复字幕。模型选择、代码执行、角色移动必须依次发生。
4. **固定声音。** 优先沿用用户批准的参考音。Next 的参考音通过 references 配合 @voice1 使用；不是把返回 audio.id 当 voice ID。接口限制要按使用时文档核对。
5. **分段生成。** 保存原始提示词和请求结果；不按返回 token 数猜时长。不满意只重做有问题的段，不无条件批量重试。
6. **核对实际声音。** 用 scripts/asr_qwen.py 调用 Filetrans 做转写与时间戳检查（接入状态见 [Qwen ASR 接入](Qwen-ASR接入.md)），严重跑词必须处理；相近发音、英文误识别不能直接断言模型念错。没有听音能力，就不声称完成主观试听。
7. **对齐字幕和事件。** 优先使用 Filetrans 返回的词级定位与字幕草稿，离线备用 scripts/align_whisper.py；校正文字、断句、标点。记录选择、执行、移动、音效等事件时间。新音频必须重对齐。
8. **剪辑与音量。** 缩短过长的低能量空白，给语音两侧留保护区；保留原件、记录删减范围。分别统一音量，防止拼接跳变。
9. **渲染并验收。** 先导出关键帧和短片段修布局、逻辑，再生成整片。交付视频、SRT、代码、事实说明及验收边界。

新主题可沿用流程、字体、字幕和绘图基础；口播、比喻、场景和动画通常要重新设计。
