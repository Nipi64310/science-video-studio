# 中文科普视频制作

先确定仓库根目录，读取根目录 README.md。把本 Skill 当制作规程，把 examples 当已完成的具体实例，不把 Jev 的游戏剧情当通用模板。

## 先完成内容设计

1. 把主题收敛成观众看完能回答的一个问题。研究一手来源，将可用事实写成正文并附追溯地址，不只罗列链接。
2. 区分官方宣传、社区自述、自己的推论和实测。原创动画及假设数值标明示意，禁止编造请求日志、跑分、计时器或实测翻车。
3. 用自然中文写口播，保留具体动作和因果。避免客服换鞋式生硬切入、英翻中、“问题？答案。”的套路及不必要的口头禅。
4. 写逐镜目标、口播、画面变化、声音和语义锚点。让画面帮助理解关系，不把文章切成幻灯片。
5. 先固定一套视觉主题。切换配色应有叙事理由；不要把已有三分钟实例的明暗交替当作所有新片的默认要求。

## 固定音色，再制作

- 已有用户批准的参考音时直接沿用，不反复请求确认。私人参考音放在 local_media 中。
- 使用 scripts/tts_next.py，认证从环境读取。沿用当前已验证接口；若模型或服务版本变化，先核对官方文档。
- 按模型实际时长限制分段。同一参考音配合 @voice1；不要把返回 audio.id 当作音色 ID。
- 提示词采用“场景、主讲人、台词、伴随声音”的连贯写法。声音需有叙事理由，不能为了展示功能加长无意义尾声。
- 先检查有代表性的短片段，再铺开长片。生成成功与下载成功分别处理；下载失败只续下载，不重复 POST。
- 保留原始 WAV；头部帧数异常时按实际 PCM 修复工作副本，验证 PCM 一致。

## 按实际声音安排画面

1. 用 scripts/asr_qwen.py 转写核对台词，先读 docs/Qwen-ASR接入.md 的实测状态。接口失败时明确报告，不能假装完成核对；纯文字返回不等于时间戳。需要词级定位时使用可选 scripts/align_whisper.py，再对照原稿检查整句缺失、重复与无关内容。英文和同音误识别需单独判断，不盲信 ASR。
2. 严重跑词时只重做受影响片段。API 200、时长合理、引用了同一参考音都不能代替内容验收。
3. 新音频重新安排字幕和语义锚点；禁止用输出 token 数或全文字数平均分配字幕时间。
4. 需要压缩时长时先删重复内容或多余空白，保留呼吸和语音边缘保护区；不要为凑时长强行拉伸或加速声音。
5. 逐段调整音量。剪辑、重生成及拼接要记录，不能宣称一次模型调用生成完整视频。
6. 渲染前核对动作顺序，例如选择→执行→结果。检查动画中间状态，数字、指针和文字必须一致。

## 实现与验收

优先复用已跑通的 Pillow/FFmpeg 栈。用 scripts/render.py 的 --still 检查布局，用 --start/--duration 检查短片段，再导出全片。不要因缺少本地音轨自动调用在线生成。

按 references/acceptance.md 验收。明确哪些是事实核对、程序检查、关键帧目视检查、完整解码，哪些是人工听看。无音频感知能力时，不声称完成主观试听或给声音自然度虚构评分。

交付视频、独立字幕、源码、事实资料与验收记录。认证、参考人声、原始响应和签名下载地址不进入 Git；用户批准的成片与展示音轨可按明确路径放行，其他生成媒体默认排除；提交前运行 scripts/check_repo.py。
